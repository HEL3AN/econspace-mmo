# Project review, 2026-10-11

A fresh-eyes review of the whole project at `main` after #332–#338. Four independent
reviewers each looked at one side: architecture and code health, gameplay and design,
netcode and MMO readiness, and player experience and visuals. Each was read-only: no code
was changed. This file keeps their findings so that none of it is lost. Every item that
calls for work has an issue (listed at the end).

The owner's own summary page: https://claude.ai/artifact/5P6yZgjtyNFkrA5BoxyvkT

## Verdict

**The technical base is strong; the game is not there yet.** The authoritative server,
deterministic generation, the living world of factions, agents as players, and tests on
three compilers are careful work with the reasons written down. But a player cannot buy
goods, there is nowhere to dock beyond the wormhole, dying costs nothing, and progression
ends at 4,200 credits. The last ~30 PRs were rendering, the UI framework, sieges and
macro benchmarks; the next should be about what makes an evening worth playing. There
are a few holes to close before anyone outside plays on the server.

## Urgent: holes and data loss (#341)

Every item was found independently by at least two reviewers. All are small (S).

1. **Any client can mint money.** `Command.debugMoney` (`Protocol.h:122`) is honoured
   unconditionally at `main_headless.cpp:150`. F1 sends it, and so can any agent or raw
   socket: at 60 commands a second, 60,000 credits a second. Gate it behind a server dev
   flag or remove it; the "[debug] F1: +money" line also ships in Release.
2. **Saves are not atomic, and a corrupt save is silently replaced.** `SaveWorld` and
   `SaveAccount` write with `std::ofstream` over the live file (`Simulation_World.cpp:604`,
   `Simulation_Player.cpp:983`); a write failure is ignored. On startup `Result::Corrupt`
   falls into `InitGalaxy()` (`main_headless.cpp:115-118`): a crash mid-checkpoint
   truncates `world.json`, the next boot starts a new galaxy, and 60 s later it overwrites
   the evidence. A truncated account file makes `ReadStoredAuth` fail, so the account looks
   new and **whoever logs in first registers a secret on someone else's name**. Fix: write
   tmp, flush, rename (`MoveFileExW(MOVEFILE_REPLACE_EXISTING)` on Windows); rotating
   `.bak`; Corrupt is fatal for the world and refuses login for an account.
3. **Command floats are not clamped.** `turn` is stored as-is (`Ship.cpp:135`) and applied
   as `heading_ += ctrlTurn_*turnSpeed*dt`: `turn: 50` turns instantly. A JSON `1e39`
   overflows to `inf`, then NaN heading and position are broadcast to the whole system.
   `navVia`, `orderPoint`, `navRange`, `navStopDist` are unchecked too. Clamp every field
   in `DecodeCommand`, reject non-finite values, and fuzz the decoders.
4. **Pilot and pilot are one file but two sessions.** `ValidAccountName` accepts both, NTFS
   treats them as one file, and the one-session check compares strings exactly, so cargo and
   structures can be duplicated. Lowercase names.
5. **Watching the world changes it.** `BuildGalaxyState` calls `RecountAgg` on every system
   once a second while a client is connected (`Simulation_Snapshot.cpp:338`).
   `MaintainWorld` derives losses from the difference between recounts
   (`Simulation_Agents.cpp:730-742`), so with players online roughly half of all NPC losses
   never reach suppression or `lostPirates`/`lostPolice`. Read the aggregate without
   recounting.
6. **No connection control.** Listen backlog is 4 (`Tcp.cpp:216`); no cap on total clients,
   per-IP connections or registrations; every login spawns a ship. Each connection may hold
   8+4 MB of buffers, so about 100 hostile sockets exhaust RAM. Add `MAX_CLIENTS`, per-IP
   limits, a registration rate limit, login backoff, a larger backlog, a 64 KB frame cap
   and a 1 MB backlog cap.
7. **Fair-play leaks.**
   - The session and ship vanish the moment the socket closes, so logging off escapes
     combat. Keep the ship in space about 30 s.
   - `HiddenInCover` hides a player from NPCs but other players still receive their
     position (`Simulation_Snapshot.cpp:182-200`).
   - A ship that stops sending commands freezes, and a 1 s burst is then accepted (lag
     switching).
   - A version mismatch drops the socket with no `Bye`; it should name both versions.

## Strengths

- **The chronicle is real content.** "Pirates founded a hidden base in W-5.2", "Traders
  Guild surveyed W-2.1: 5 belts, pirates": a frontier that changes by itself in an hour.
  Few indie MMOs have this; it is the clearest thing that sets the game apart.
- **Naming a system first, once, for everyone.** A cheap, permanent bragging right that
  fits the wormhole premise.
- **Agents follow exactly the rules humans do.** Every verb is an MCP tool and an order
  the server carries out over time, which makes "hire AI pilots" credible.
- **Ship stats come from parts**, and NPC doctrines fly the same designs: one foundation
  for fitting, industry and player designs.
- **Structures have a full life:** build, dismantle, siege, wreck, decay, police, the law.
- **Module boundaries hold.** `src/engine` never includes game, sim, net, agent or editor
  headers; the client never includes `Simulation.h`; `netproto` is compiled once; movement
  is one function used by prediction and authority.
- **Determinism is a rule, not a hope.** `Gen::Rng` keyed by what is generated, a golden
  hash on three compilers, `GENERATOR_VERSION`, motion as `f(time, seed)`.
- **Substantial tests:** 361 doctest cases in about 14.9k lines against about 37k lines of
  source, linking the real `Simulation`; logic split from drawing so it can be tested.
- **CI exercises behaviour:** three OSes, live-socket tests with several clients, the agent
  reference checked against the binary, the example bot run.
- **The reasoning is written down** (DECISIONS.md, issue numbers in comments, CLAUDE.md
  trip-wires) and there are 0 TODO/FIXME markers.
- **The transport defends itself** (frame and backlog caps, hello/login timeouts, a tick
  budget against speed hacks); **versioning is disciplined**; **login is a challenge and
  an answer** with a 100k-round stretch.
- **Cold systems are cheap:** 1000 systems with nobody on cost 0.11 ms per tick.
- **The generated look holds up:** planets with terminators, bands and moons read as one
  family; the station kit reads as engineered.
- **The window system is coherent**, and the overview-and-actions model is really there: a
  player can fly from the overview alone.

## Gameplay and design

Facts the review rests on: no buy in the market (3 resources; the agent's `trade_run`
prompt says "there is no buy tool yet"); the generated region has no stations
(`Region.cpp:787`, `sys["stations"] = []`); `ServerRespawnPlayer` teleports and repairs, so
death costs only cargo; progression is 4 hulls from 0 to 4,200 credits; players cannot
build outposts (faction-only blueprints); PvP deals no damage (#94); in one hour with no
players, pirates founded 4 hidden bases and 14 of 21 systems ended at security 0.

Biggest gaps, with proposals:

1. **No trade loop.** Add buy, then 6–10 goods in a 2–3 tier chain (ore, refined,
   components, consumables). Each system's goods come from what is generated there; NPC
   haulers move them so prices differ between systems.
2. **The frontier has no anchor.** Factions upgrade an outpost into a small station with a
   market and a job board; players build a depot or outpost with a market (#39 tier 2).
   (Now part of world generation v2, #342.)
3. **Losing costs nothing.** Lose the ship and what is fitted, keep the hangar; cheap
   insurance; the starter hull free and unlimited; risk rises with region depth.
4. **Progression stops at 4,200 credits.** Modules as items and fitting (#279), growing
   costs and hull tiers; strong modules unlocked by faction standing; later production
   (#333). Fitting fills hours 2 to 20.
5. **The living world does not pay the player.** Faction plans post jobs: escort the
   construction convoy, deliver 40 Iron to site X, survey W-4.2. Pirate bases post
   bounties. Selling survey data makes exploration a profession. Rated the most important
   slice for showing what sets the game apart.
6. **No social structure.** Minimal corp (shared standings, shared structure permissions),
   local chat, and PvP settled by system security and controller (#94): legal where
   security allows, a lootable wreck, no attacks while docked or warping.
7. **Exploration is just visiting.** A scan verb that reveals hidden things (pirate bases,
   rich belts, derelicts, the next wormhole); the first to scan is credited in the
   chronicle.
8. **Onboarding (#7) is empty.** A short chain: dock, a mining job, sell, buy a module, a
   delivery through the wormhole, ending with a bounty on a real pirate base from the
   chronicle.

Recommended order toward an evening-long vertical slice (#7): buy goods and a 2-tier goods
set; ship loss and insurance (before content, so everything after is designed with risk);
module items and fitting; a faction station in the region; jobs posted from faction plans;
scanning, discovery and selling intel; a player depot/outpost with a market and rules of
engagement (#340); corp-lite, local chat and PvP rules (#94); industry v1 (#333); the
onboarding chain and a wormhole-opening scenario (#7). Fleets (M5, #32) and the client
builder (M8) come after: they multiply a loop and cannot replace one. Hired agent pilots
could come early, as a cheap way to show the agent premise.

Risks to the vision: infrastructure keeps growing while gameplay does not; the living
world stays a news ticker unless it posts work and pays; pirates take over (a
counterweight players are paid to provide); agents that never sleep flatten prices and
drain belts (decide early: rate limits, fees, depletion, or agents as hired crew); free
design converges on one optimal design (keep frames and slots as constraints); too much
scale for too few people (region size should follow players, see #342); no audio (#2).

## Netcode, performance and MMO readiness

What breaks first:

| Players | What happens |
|---|---|
| 50 | CPU fine (~0.6 ms/tick). Bandwidth ~3.75 MB/s out and ~1.5 MB/s in: too much for a home uplink. A crowd at the start system grows snapshots quadratically. The urgent holes get used on day one. |
| 500 | Ticks spike past 100 ms (measured worst 118.7 ms). A hub with 100+ players makes snapshots tens of KB each; send backlogs fill and clients are dropped. Saves stall. |
| 5000 | One thread, one process, one JSON world file: sharding by region and binary delta snapshots, which is a rework. |

Measured with Release macrobench at 1000 systems, one player per system, networking
excluded: 50 players 0.60 ms mean / 9.6 ms worst; 500 players 6.0 ms / 118.7 ms with
top-up at 18.8 ms per pass; every system hot 14.2 ms mean. A synchronous world save every
60 s costs 40–56 ms (about 3 ticks), and charting a system writes the world too
(`main_headless.cpp:942`).

Risks beyond the urgent list:

- **Bandwidth.** The full command (~35 fields, ~450 B JSON) goes 60 times a second (~30
  KB/s up). Snapshots are full-state JSON with no deltas and no interest culling across a
  million-unit system, and carry mission text and the whole player view every time.
  `snapshotAcc = 0.0` throws away the remainder and `sleep_for(4ms)` sleeps ~15.6 ms on
  Windows, so the rate is ~16 Hz, not 20 (which fits 45 KB/s ≈ 2.9 KB × 16). The galaxy
  message is ~90 B per visited system per second: ~90 KB/s per client for 1000 systems.
  Fix: send only changed command fields (later binary), `snapshotAcc -= interval`, delta
  the player view and missions against the last acked snapshot, send the galaxy only on
  change. Target 15 KB/s down, 5 KB/s up. (M)
- **O(n²) loops.** `BuildSnapshot` loops every session for every recipient
  (`Simulation_Snapshot.cpp:182`); NPC targeting checks every NPC against every ship
  (`Simulation_Agents.cpp:210-216`); top-up loops systems × sessions. Fix: a spatial grid
  per system, an area of interest by distance with a cap, saves on a separate thread from
  a snapshot of the state, top-up spread across ticks. (M/L)
- **Login is only as strong as an open wire.** `stored` crosses in clear text on
  registration; the account file's `stored` is a password equivalent; nonces come from
  `mt19937_64` seeded from `random_device` (deterministic on older MinGW), the clock and a
  stack address; no per-IP or per-account rate limit. Fix: TLS or a Noise/libsodium
  handshake, `BCryptGenRandom`/`getrandom`, backoff, later SRP/OPAQUE. Tell testers to use
  a throwaway secret. (M)
- **No ops tooling.** `printf` logs with no timestamps or levels, no metrics beyond
  `NetStats`, no admin kick/ban/broadcast/shutdown warning, no backups, and an `acc` cap of
  0.25 that silently slows world time under load. Fix: timestamped log file, a
  per-minute metrics line (tick mean/p99, bytes per client, clients, save ms), admin
  commands on stdin; host on a VPS, Release build, firewall, a process supervisor. (M)

Hardening plan for a 20–50 stranger playtest, in order: the urgent list (#341); bandwidth
basics; ops tooling; tell testers there is no transport encryption; CI with a named build
type, ASan/UBSan and decoder fuzzing.

## Architecture and code health

1. **`Simulation` is a god object:** 6,583 lines over 11 TUs, about 87 public methods and
   27 members, covering galaxy, factions, sieges, outposts, construction, NPC AI, player
   verbs, persistence, snapshots and the RNG; 78 direct `sim.Step*` uses in tests. Splitting
   into TUs (#17) organised files, not dependencies. Extract subsystems that own their
   state: `FactionDirector` (minds, plans, due queue, chronicle, sieges),
   `StructureRegistry`, `Persistence`, `PlayerVerbs`. (L, incremental)
2. **Command dispatch lives in `main()`'s file and is untested.** `HostStepPlayer`
   (`main_headless.cpp:136-245`) is the whole verb table; `RunHost` is 425 lines; the file is
   1,733 lines with five smoke tests. `Proto::Command` is a flat struct of ~37 fields sent
   at 60 Hz. Move dispatch to `Simulation::ApplyCommand`, split one-shot verbs into a
   tagged `Action` message, move the selftests out. (M)
3. **Load strictness is inconsistent.** Archetypes, theme and ship designs reject unknown
   fields (#191), but `Factions::Load` returns silently on a missing file and maps unknown
   ids to `Independent` and unknown stances to `Neutral` (`Faction.cpp:48-69,100-160`), and
   `WorldLoader` uses ~30 `.value()` reads and only warns on unknown planet types and
   station roles (`WorldLoader.cpp:205,227`). Pins are written in that format. Apply #191
   to factions and system documents. (S–M)
4. **Factions are a compiled enum.** `FactionId {Independent, TradersGuild, Syndicate,
   Pirates}`, `FACTION_COUNT = 4` used in 22 places, fixed arrays for relations and minds.
   Player corporations and generated factions (#342) cannot exist. Make `FactionId` an index
   into a loaded table. (M)
5. **Content registries are process-wide globals** (`g_archetypes`, `g_ships`,
   `g_blueprints`, `g_materials`, `g_modules`, faction arrays) and ship choice crosses the
   wire and saves as a catalogue index (`refitShip`, `buyShip`). Adding or reordering a
   design silently retargets commands and saved owned ships. Use stable string/hash ids;
   make the registry an instance owned by the world. Needed before #151. (M)
6. **The client's netcode is untested.** Prediction and replay in `GameNet.cpp` (around
   `pendingInputs_`) and interpolation have no tests, though CLAUDE.md calls their
   agreement the invariant that breaks silently. No sanitizer job, though #46 was a
   use-after-free. Extract a `Prediction` class and test server and client stepping the
   same commands; add ASan/UBSan. (M)
7. **Scaling the per-player side is unmeasured.** One thread sleeping 4 ms per loop; each
   session builds and JSON-encodes its snapshot ~20 times a second; saves are synchronous;
   systems live in `std::map<std::string, SystemState>` looked up by string in every
   `SystemOf(s)`. Add a `netbench` (N fake sessions in one system) before M5; then encode
   once per system and patch per recipient, binary encoding, saves off the main thread. (M
   to measure, L to fix)
8. **The build compiles the same files several times.** The `Simulation_*.cpp` files and
   ~10 more are listed for both `econserver` and `tests`; `ShipType.cpp` builds into 4
   targets. CI configures without `CMAKE_BUILD_TYPE` (against CLAUDE.md; `CMakeLists.txt:213`
   forces `-O2` on `Auth.cpp` to compensate); the ~70-line two-clients script is copied in
   two jobs; the agent selftest uses `sleep 5`. Add a `simcore` static library, a build
   type, and move the shared CI script to `tools/ci/`. (S) (Parallelism was bounded in #338.)

Docs out of date: ARCHITECTURE.md's "Planned directions" lists the million-unit system,
the generated region and construction, all built; its TU list misses Factions, Build,
Outposts, Sieges and the editor's Survey, Pins, Region; it says missions live in
`Simulation::missions_` (they are per session); it calls `TcpTransport` winsock-only.
ROADMAP.md says systems are ~25k units across, that the agent has nine tools (~20 now;
same in `docs/agents/README.md:62`), that #38's persistence remains (done in #286), and
presents M7 as future. HANDOFF.md is five weeks old. Some code comments describe the past
as the present (`main_headless.cpp:134-135`, `:231`, the CMake comment on `econserver`).

## Player experience and visuals

Reviewed on the Intel UHD 620 laptop, 11 screenshots, before the Fleet console theme
(#336) merged; some window findings (density, contrast) were addressed there.

1. **The star's colour swallows the world.** Station, orbit band and ship share one hue;
   figure and ground merge. Keep the star as key and rim light, cap how much its colour
   saturates albedo, give stations their own palette. (The owner chose to keep the halo
   tint itself, #259; this is about the objects.)
2. **You cannot find your own ship:** a ~30 px sliver the colour of the station behind it.
   Draw an instrument-layer bracket or chevron and a heading/velocity tick (does not break
   #117).
3. **The world view shows no threat.** Allegiance lives only in instruments; the overview's
   type column is uncoloured. Add a standing chip to overview rows and instrument brackets
   on ships in the world view, coloured by standing as the HUD, as EVE does.
4. **The first 30 seconds have no direction.** Add a one-line goal prompt ("Dock at Aurora
   Hub to pick up work") with a pointer; rail tooltips and hotkeys (labels done in #336).
5. **Docking dumps windows on top of each other**, and Settings is restored open across
   sessions. A docked default layout that tiles; never restore Settings. (Overlap handled
   by `DeskLayout::Arrange` in #336.)
6. **Text too small and low-contrast** (~10–11 px grey); the UI does not grow at 1080p.
   13 px minimum body, 4.5:1 contrast, DPI auto-scale, radar hover labels. (Partly #336.)
7. **Allegiance colours are not colour-blind safe:** you green / hostile red is the
   deuteranopia pair; map rings and security colours repeat it. Add redundant shape
   (diamond vs circle on the radar), move "you" to cyan/white, an alternative palette, a
   text label with every colour.
8. **One action, different names:** "Keep" in the selected-item window, "Hold 3500 from it"
   in the context menu, which has no header naming its target. One verb per action from the
   `Actions` list; a context-menu header with target and distance.
9. **Sensor glyphs collide:** the legend lists "planet" twice (o and O); gate "0" and planet
   "O" look alike; planet/moon pairs overlap. A distinct gate glyph, named entries, offset
   shared cells.
10. **The treatment and the HUD cost too much.** 720p: frame 12 ms, treatment 6.4 ms GPU.
    1080p: frame 22 ms (46 fps), treatment 13 ms GPU, present 6.8 ms. The HUD costs 7.3 ms
    CPU at 720p and 13.8 ms at 1080p for a handful of windows: per-frame text layout or
    measuring is likely. Half-resolution treatment or fewer passes, a "low" preset; profile
    the HUD; draw editor captions after the treatment.

Smaller: the galaxy map is mostly empty with tiny labels; the overview cuts its last row
in half; 51 font warnings ("size bigger than expected" for '|').

Recommended order after the themes: world readability (neutral space, own-ship marker,
standing brackets and chips); accessibility (size, contrast, DPI, colour-blind palette);
performance (HUD CPU, cheaper treatment); the first 30 seconds (goal prompt, layouts);
action naming; instrument polish (sensor glyphs, radar labels, map); then art depth
(station albedos, engine glow, small-ship silhouettes at warp-scale zoom).
